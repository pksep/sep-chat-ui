# SEP Chat — удалённый интерфейс

## Новая схема v4 (APK 2.0.0 / 20001)

Адрес для 20001: https://pksep.github.io/sep-chat-ui/manifest-v4.json

Первоначальная APK 20000 продолжает использовать manifest.json (v3).
Эти адреса независимы: не заменять старый файл новой схемой.

- manifest-v4.json — безопасный Native-документ для 20001; удалённая картинка отключена.
- manifest-v4-20002.json — QR-окно для исправленного native-кода 20002, без изменения веб-кнопки.
- example-v4-profile.json — новые кнопки QR/статуса, форма, диалог и цепочка действий.
- rollback-v4.json — отключение v4; для применения опубликовать его содержимое
  как manifest-v4.json с новой revision.
- catalog-v4.json — 203 адаптера текущего Android.

V4 добавляет формы, состояние, шаблоны/списки, страницы/диалоги и разрешённые
нативные действия. В components можно использовать style и явное mode:replace
без Native. По умолчанию decorate по-прежнему требует один Native.
Новые экраны собираются из runtime.views/pages/dialogs; Scene подключает view
в нужный адаптер. Возможности явно перечисляются в runtime.permissions,
права аккаунта и подтверждения остаются в Android. Для v4 minVersionCode >=20001.

Полный контракт: [CONTRACT_V4.md](CONTRACT_V4.md).

### Скачать Android-приложение из веб-профиля

Кнопка добавлена в веб-клиент chat_client/main, PR #498. Для неё новая APK
не нужна. Изображение QR и адрес APK читаются из общего удалённого config ниже.

- Адрес скачивания меняется в [android-download.json](android-download.json), поле `apkUrl`.
- По умолчанию это последний публичный выпуск: `https://github.com/pksep/sep-chat-ui/releases/latest/download/SEP-Chat.apk`.
- QR кодирует постоянный адрес `https://pksep.github.io/sep-chat-ui/android/`.
  Страница читает актуальный `apkUrl` и начинает скачивание. Новая версия APK
  или замена ссылки не требуют менять уже показанный/сохранённый QR.
- Изображение QR: `assets/android-download.png`. Для замены на другое изображение
  менять `qrImageUrl` в download JSON.
- `enabled: false` в download JSON прекращает выдачу ссылки.

Автоматическая раздача APK из собственного MinIO описана в
[ANDROID_DOWNLOAD_STORAGE.md](ANDROID_DOWNLOAD_STORAGE.md). Переключение ссылки
выполняется только после загрузки и проверки публичной копии APK.

После обычного commit Pages публикует конфигурацию. Workflow, использующий
`GITHUB_TOKEN`, запрашивает сборку Pages явно.
Скачивание по QR читает текущий download JSON при каждом открытии; веб-профиль —
при каждом открытии QR-окна. Данные аккаунта и авторизация не передаются.

APK публикуется в GitHub Releases как `SEP-Chat.apk`, без добавления бинарника в Git.
Следующий выпуск должен иметь больший versionCode; публикация проверенной APK
выполняется `chat_android/tools/publish-android-download.py` с её отчётом проверки.
Он сначала создаёт черновик, сверяет SHA-256 загруженного файла и только затем
делает выпуск последним. Предыдущие выпуски сохраняются.

Дополнительная native-проверка обнаружила ошибку TLS close на Main в 20001.
Для 20001 и будущей 20002 сохранён Native-дизайн без новой кнопки скачивания.
Исправление SDK сохранено в Android-коде для следующего выпуска; новая APK
не нужна для веб-кнопки. Версия/полнота native-выпуска отслеживается в Android-плане.
Перед публикацией использовать актуальный Android-парсер; он проверяет все
файлы v3/v4 и каталог. Данные аккаунта, токены и ключи сюда не добавлять.
Новый нативный тип/бизнес-API всё ещё требует APK; новые сочетания имеющихся
компонентов и действий доставляются JSON. Исходные правила v3 сохранены ниже.

Публичные JSON-интерфейсы и remote config для Android-приложения SEP Chat.
Этот репозиторий не содержит данные пользователей, сессии или исходники приложения.

Адрес конфигурации: https://pksep.github.io/sep-chat-ui/manifest.json

## Файлы

- `manifest.json` — активная конфигурация. Начальная публикация сохраняет штатное оформление.
- `rollback.json` — отключение удалённого оформления.
- `example-profile.json` — пример изменения высоты строк профиля и кнопки проверки обновления.
- `catalog.json` — разрешённые ID компонентов, свойства, локальные данные и действия.
- `.nojekyll` — публикация файлов GitHub Pages без преобразования.

## Изменение

Редактировать `manifest.json` и выполнить commit в `main`. Использовать схему 3
и `minVersionCode: 20000` для SEP Chat 2.0.0. При каждом изменении обновлять
`revision`. Для визуальных изменений устанавливать ограниченный срок действия
`expiresAtEpochSeconds`, например неделю. Базовый документ имеет долгий срок,
поскольку не меняет оформление.

JSON допускает только зарегистрированные компоненты из каталога. В каждом
компоненте обязателен ровно один `Native`. Данные и действия остаются локальными
в Android; произвольный код, ссылки или сетевые команды не исполняются.

До публикации проверить файл настоящим Android-парсером в `chat_android`:

```text
gradlew.bat :app:testDebugUnitTest --tests ru.pksep.chat.remoteui.RemoteUiPublishedManifestTest -PketoyManifestFile=<абсолютный путь к manifest.json>
```

GitHub Pages публикуется из `main`, каталог `/`. Приложение проверяет изменения
при активной работе не чаще раза в 30 минут. Готовый документ применяется при
следующем открытии поверхности, сохраняя текущий ввод. CDN также может задержать
доставку. При отсутствии сети используется последний валидный кеш; без кеша —
штатный интерфейс приложения.

## Откат

Заменить содержимое **`manifest.json`** содержимым `rollback.json`, изменить
`revision` и выполнить commit. Наличие отдельного `rollback.json` само по себе
ничего не переключает: Android читает только настроенный адрес `manifest.json`.
Включение обратно — восстановить проверенную конфигурацию с новой ревизией.

Новые типы компонентов и бизнес-функции требуют обновления Android-приложения.
